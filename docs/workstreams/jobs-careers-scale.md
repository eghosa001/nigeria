# Jobs & Careers scale workstream

Branch: `scale-jobs-careers`

Base commit: `79f494ed1700389ed79bfd18fe51f531d1847e91`

Long-range target: **20,000 useful indexable jobs/career URLs** within the MyNigeriaGuide Million-Search Expansion.

Read and obey `AGENTS.md`, `config/scale-targets.json`, and `docs/SCALING.md`.

## Scope

Own the Jobs & Careers pillar only.

Primary surfaces:

- `/jobs`
- `/jobs/[slug]`
- `/jobs/open-now`
- `/jobs/deadlines`
- `/jobs/government`
- `/jobs/private`
- `/jobs/graduate`
- `/jobs/internships`
- `/jobs/nysc`
- `/jobs/engineering`
- `/jobs/remote`
- future employer/location/profession hubs

Primary data/code ownership:

- `lib/jobs.ts`
- jobs-specific routes/components/data/scripts
- jobs-specific tests only

Avoid entertainment, services and travel datasets.

## Search demand strategy

Prioritise:

- current Nigerian vacancies;
- federal/state recruitment;
- graduate trainee programmes;
- internships;
- NYSC opportunities;
- engineering;
- health;
- technology;
- banking/fintech;
- FMCG;
- telecom;
- oil & gas/energy;
- NGOs/development;
- remote Nigeria roles;
- employer careers;
- salary/qualification/application guidance where sourceable.

Prefer employer-direct vacancy pages and official recruitment portals.

## Job page model

Every active job page should include:

- exact role;
- organization;
- location;
- employment type;
- current status;
- deadline when published;
- audience/fields;
- qualifications;
- requirements;
- required documents;
- application steps;
- official application URL;
- fee/scam warning;
- verification timestamp;
- source notes.

Do not invent salary, deadline or qualification requirements.

## Lifecycle rules

Jobs change faster than every other pillar.

Every record should be capable of moving through:

- open;
- screening;
- training;
- upcoming;
- career-page;
- closed/expired.

Expired jobs should not remain falsely presented as open.

Where useful for historical/search intent, preserve the page and clearly mark it closed rather than deleting it immediately.

## Scale architecture

This pillar will likely hit the database threshold first.

Before the jobs catalog exceeds **5,000 records**, move it behind the D1 content-store/data-access boundary.

At scale:

- query D1 by status/location/field/employer/deadline;
- paginate server-side;
- use FTS5 for search;
- add scheduled expiry checks;
- add source re-verification queues;
- cache category/hub pages appropriately;
- do not compile all jobs into one Worker module.

## Expansion milestones

### Milestone 1 — live employer coverage

Expand active and official employer-direct opportunities across major sectors.

### Milestone 2 — employer and profession hubs

Create strong discovery paths for companies, cities and professions where enough real jobs exist.

### Milestone 3 — automated freshness

Add scheduled expiry/re-verification logic once the D1 catalog is live.

### Milestone 4 — 20,000 useful URLs

Reach the target through real vacancies, employer/career pages and durable career guides—not autogenerated empty location/keyword combinations.

## Structured data

When valid and complete, active vacancy detail pages should expose JobPosting structured data consistent with the visible page.

Expired jobs must not keep misleading live JobPosting status.

## Merge-conflict boundary

Prefer jobs-only files. Do not edit:

- `config/scale-targets.json`
- `AGENTS.md`
- entertainment/services/travel datasets

unless a critical shared fix is unavoidable.

Keep any unavoidable shared edit minimal and in its own commit.

## Validation

Follow the owner's minimal-test rule. Run only directly relevant job/data checks. Do not manually run the full repository suite.
